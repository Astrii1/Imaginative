### A contextual frontend design skill for Claude Code

Most frontend design tools have a strong default aesthetic. Usually that means polished SaaS: large typography, rounded cards, gradients, generous whitespace, dashboards and a familiar collection of UI patterns.

That's useful when SaaS is what you're building.

This skill is for everything else.

## What it does

Imaginative helps Claude choose a visual language based on the thing it is actually building.

It considers:

- The product and what it does
- The people using it
- The environment it belongs in
- The task the website needs to support
- The relevant design genre
- Historical and cultural conventions
- Information density
- Typography and layout
- Photography, video and other media
- Interaction and animation
- Accessibility and usability
- Reference websites and visual examples

A government service, a newspaper, a traditional barber, a financial terminal, a legal AI product and a personal website should not all arrive at the same design.

References are stored as structured metadata rather than simply collecting screenshots.

The goal is to capture what makes a design work, what it communicates, where it is appropriate and what should be avoided when taking inspiration from it.

## Examples

The planned demo site will show the same fictional product designed in several completely different visual worlds.

For example:

- Contemporary SaaS
- GOV.UK-style institutional
- 2000s web
- Editorial newspaper
- Bloomberg-style information density
- Netflix-style media discovery
- Brutalist
- Handmade personal web
- Cinematic professional services

The point is to demonstrate that the same product can produce very different interfaces when the context changes.

## Evaluations

The project includes evaluation scenarios designed to test whether the skill actually produces meaningful contextual differences.

Examples include:

- A traditional British barber
- A Welsh holiday-let compliance tool
- Legal AI for major law firms
- A financial dashboard
- A local plumber
- A newspaper
- A 2004 utility website
- An artist portfolio
- A streaming service
- A government service
- An independent pub
- Private banking
- Technical documentation
- An online forum
- A deliberately ugly but usable calculator

A successful result should reflect the intended context rather than simply changing colours, fonts or border radii.

## The principle

Websites should feel like they belong to the thing they represent.

Sometimes that means polished modern software.

Sometimes it means a dense table, blue hyperlinks and tiny text.

Sometimes it means something strange.

That's the point.
